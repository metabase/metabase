# Autonomous Development Workflow

- Do not attempt to read or edit files outside the project folder
- Add failing tests first, then fix them
- Work autonomously in small, testable increments
- Run targeted tests, and lint continuously during development
- Before relevant edits, read applicable project guidance and the loaded skill's required references in full, including `@` references that your tools don't expand automatically. Searches and excerpts don't replace required reads. Reuse guidance already read for this task unless it changes, and report any required guidance you can't access.
- Prioritize understanding existing patterns before implementing. Check reused patterns against current guidance; a legacy example does not override a prescribed convention.
- Don't commit changes, leave it for the user to review and make commits
- Minimize comments. Document only non-obvious intent, trade-offs, or constraints that the code itself cannot convey. Do not narrate what the code does — keep code self-descriptive through naming and structure.
