# Public-release review of papercut write-ups

The files named in your batch are papercut write-ups (`andrei.claude.<slug>.md`) generated by agents from one engineer's Claude Code transcripts. They will be pushed to the PUBLIC github.com/metabase/metabase repository, where anyone can read them forever. Your job is to make each file safe to publish, or delete it. Be strict. When unsure, cut the passage; when a file would lose its point after cutting, delete the file.

## Delete the file if its subject involves any of

- The engineer's own notes and working files: memory notes, CLAUDE.md or other agent instructions, work log, standups, brag or review docs, a personal docs repo, how they organise their day.
- People: colleagues, reviewers, managers, team dynamics, feedback about anyone, career, performance, hiring, interviews.
- Writing style, tone or wording preferences; etiquette or permission for posting on Slack, Linear, GitHub or Notion.
- Repositories other than metabase/metabase (for example evals, data-stack, dbt-models, stats tooling), unless the papercut is purely about a public tool and the repository is incidental. In that case rewrite so the other repository's internals are gone.
- Other companies or side projects; personal infrastructure (servers, SSH, keys, network, devices, accounts); security incidents, leaked or exposed credentials, auth or permission weaknesses, anything that reads as an unfixed vulnerability or exploit recipe.
- Customers, customer data, query results with real data, incidents.
- Anything embarrassing for the engineer or anyone else.

## Keep, after editing, only if

The papercut is about the public metabase/metabase code, its CI and dev tooling, or widely used public tools (git, gh, GitHub Actions, bun, node, mise, Clojure tooling, clj-kondo, Claude Code, Codex, MCP servers, browsers, shells), and after your edits nothing from the list above remains.

## Edit kept files

- Remove quoted user messages and agent thinking. Paraphrase in neutral technical terms only when needed ("the user pointed out the test had not run").
- Remove any mention or quote of the engineer's notes, memory files, CLAUDE.md contents, work log or standups. A status of `documented-still-hit` may stay, with its note reduced to `# a local note covered it`.
- Remove names, GitHub or Slack handles, emails, Slack, Linear, Notion and other internal URLs, ticket IDs, internal hostnames, IPs, and secrets (a `[REDACTED...]` marker may stay).
- Remove emotional or evaluative commentary about anyone ("was annoyed", "frustrated", profanity, jokes).
- Keep the technical substance: commands, error messages, file paths inside metabase/metabase, code identifiers, tool output, suggested fixes.
- Keep the file structure valid: the `---` frontmatter with title, slug, kind, impact, severity, status, area and the occurrences block (transcript, lines, date, jev); `## Summary` must remain. Do not rename files or change slugs. No em dashes.

## Log

Append one line per file to the log file named in your batch:

- `KEEP <file>`
- `EDIT <file>: <what kind of thing was removed, in generic words>`
- `DELETE <file>: <generic reason category>`

Reasons stay generic ("personal notes", "other repository", "people", "security"), never the sensitive detail itself. Touch nothing outside your batch's files and the log. Reply with one line: kept, edited and deleted counts.
